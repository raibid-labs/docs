# Rust-Doc Bridge Plugin - Implementation Details

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────────┐
│                     Markdown Documentation                       │
│  "See [[MyStruct]] for details and [[my_function]] examples"   │
└──────────────────────────┬──────────────────────────────────────┘
                           │
                           ▼
        ┌──────────────────────────────────┐
        │    ObsidianFlavoredMarkdown      │
        │  (converts [[name]] to links)    │
        └──────────────────┬───────────────┘
                           │
                           ▼
        ┌──────────────────────────────────┐
        │       RustDocBridge Plugin        │
        │  (resolves to rustdoc URLs)      │
        └──────────────────┬───────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│                   Rendered HTML Output                           │
│  "See <a href="/api/my_crate/struct.MyStruct.html">MyStruct    │
│   for details and <a href="/api/my_crate/fn.my_function.html"  │
│   >my_function</a> examples"                                    │
└─────────────────────────────────────────────────────────────────┘
```

## Plugin Architecture

### File Structure

```
quartz/
├── plugins/
│   ├── transformers/
│   │   ├── rustdoc-bridge.ts      ← Main plugin implementation
│   │   └── index.ts               ← Export the plugin
│   └── types.ts                   ← Plugin type definitions
└── components/
    └── styles/
        └── rustdoc-links.scss     ← Optional styling for rustdoc links
```

### Plugin Type: Transformer

The RustDocBridge is a **transformer plugin**, meaning it:
- Runs on the HTML AST (Abstract Syntax Tree) after markdown is converted to HTML
- Can inspect and modify links
- Has access to the full build context
- Runs once per document

Type definition:
```typescript
export type QuartzTransformerPlugin<Options extends OptionType = undefined> = (
  opts?: Options,
) => QuartzTransformerPluginInstance

export type QuartzTransformerPluginInstance = {
  name: string
  textTransform?: (ctx: BuildCtx, src: string) => string
  markdownPlugins?: (ctx: BuildCtx) => PluggableList
  htmlPlugins?: (ctx: BuildCtx) => PluggableList      // ← We use this
  externalResources?: ExternalResourcesFn
}
```

## Implementation Details

### 1. Index Building (`buildRustDocIndex`)

```typescript
function buildRustDocIndex(jsonPath: string, apiBasePath: string): RustDocIndex
```

**Purpose**: Parse rustdoc JSON and build a lookup table

**Input**: Path to `rustdoc.json` generated by `cargo doc --output-format json`

**Processing**:
```
rustdoc.json
    ├── root: ID of the crate root
    ├── crate_version: "1.0.0"
    ├── index: {
    │   "1": { name: "MyStruct", kind: "struct", ... },
    │   "2": { name: "my_function", kind: "function", ... },
    │   ...
    │}
    └── paths: {
        "1": ["my_crate", "MyStruct"],
        "2": ["my_crate", "my_function"],
        ...
    }
```

**Output**: 
```typescript
RustDocIndex = {
  "MyStruct": {
    url: "/api/my_crate/struct.MyStruct.html",
    kind: "struct",
    crate: "my_crate",
    doc: "Documentation text..."
  },
  "my_function": {
    url: "/api/my_crate/fn.my_function.html",
    kind: "function",
    crate: "my_crate",
    doc: "Documentation text..."
  },
  // ... more items
}
```

**Error Handling**:
- If JSON file doesn't exist: Returns empty index (graceful degradation)
- If JSON is invalid: Catches parsing errors and logs warning
- Missing items: Creates what's available, continues processing

### 2. Link Resolution (`resolveRustDocLink`)

```typescript
function resolveRustDocLink(
  linkText: string,
  index: RustDocIndex,
  ctx: BuildCtx,
): string | null
```

**Purpose**: Convert wikilink text to rustdoc URL

**Strategy** (multi-pass matching):

1. **Exact match**: `[[MyStruct]]` matches `"MyStruct"` in index
2. **PascalCase to snake_case**: `[[my_function]]` matches `"MyFunction"`
3. **snake_case to PascalCase**: `[[MyStruct]]` matches `"my_struct"`

**Examples**:
```
resolveRustDocLink("MyStruct", index)   → "/api/my_crate/struct.MyStruct.html"
resolveRustDocLink("my_function", index) → "/api/my_crate/fn.my_function.html"
resolveRustDocLink("Error", index)       → "/api/my_crate/enum.Error.html"
resolveRustDocLink("Unknown", index)     → null (not found)
```

### 3. HTML Link Processing

```typescript
return (tree: Root, file) => {
  visit(tree, "element", (node: Element) => {
    // Process all <a> elements
  })
}
```

**Algorithm**:

```
For each <a> element in the HTML:
  1. Check if it has class "internal" (created by CrawlLinks)
  2. Extract the link text (e.g., "MyStruct" from [[MyStruct]])
  3. Try to resolve using resolveRustDocLink()
  4. If found:
     a. Update href to the rustdoc URL
     b. Add "rustdoc" class for styling
     c. Set title attribute to "struct - my_crate"
  5. If not found:
     a. Leave link as-is (broken internal link)
     b. Will be styled as regular internal link
```

**HAST Node Structure**:
```typescript
// Before:
{
  type: "element",
  tagName: "a",
  properties: {
    href: "#",  // unresolved internal link
    className: ["internal"]
  },
  children: [
    { type: "text", value: "MyStruct" }
  ]
}

// After (if resolved):
{
  type: "element",
  tagName: "a",
  properties: {
    href: "/api/my_crate/struct.MyStruct.html",
    className: ["internal", "rustdoc"],
    title: "struct - my_crate"
  },
  children: [
    { type: "text", value: "MyStruct" }
  ]
}
```

## Data Flow

### Full Document Processing Pipeline

```
1. Input: Markdown file
   "See [[MyStruct]] documentation"

2. FrontMatter Plugin
   → Extract frontmatter metadata

3. CreatedModifiedDate Plugin
   → Add created/modified dates

4. ObsidianFlavoredMarkdown Plugin
   → Convert [[MyStruct]] → <a href="#MyStruct">MyStruct</a>
   → Result: HAST tree with internal links

5. CrawlLinks Plugin
   → Verify internal links exist
   → Mark with "internal" class

6. RustDocBridge Plugin (OUR PLUGIN)
   → Check each internal link
   → If matches rustdoc item:
     └─ Update href to "/api/my_crate/..."
     └─ Add "rustdoc" class
     └─ Set title attribute
   → Result: Some links now point to API docs

7. CrawlLinks - htmlPlugins (cont'd)
   → Finalize link processing

8. HTML rendering
   → Final HTML output

9. Deploy to GitHub Pages
   ```

## rustdoc.json Format

The plugin expects JSON output from `cargo doc --output-format json`:

```json
{
  "crate_version": "1.0.0",
  "format_version": 28,
  "root": 1,
  "includes": [],
  "index": {
    "1": {
      "name": "my_crate",
      "kind": "crate",
      "crate": 0,
      "inner": {
        "module": {
          "items": [2, 3, 4]
        }
      }
    },
    "2": {
      "name": "MyStruct",
      "kind": "struct",
      "crate": 0,
      "inner": {
        "struct": {
          "fields": [...],
          "fields_stripped": false
        }
      },
      "docs": "Struct documentation..."
    },
    "3": {
      "name": "my_function",
      "kind": "function",
      "crate": 0,
      "inner": {
        "function": {
          "generics": {...},
          "async": false,
          "unsafety": "normal"
        }
      },
      "docs": "Function documentation..."
    }
  },
  "paths": {
    "1": ["my_crate"],
    "2": ["my_crate", "MyStruct"],
    "3": ["my_crate", "my_function"]
  }
}
```

**Key fields**:
- `index`: All items (structs, functions, traits, etc.) keyed by ID
- `paths`: Maps ID → module path, used to reconstruct fully qualified names
- `kind`: Type of item (struct, function, trait, enum, etc.)
- `docs`: Extracted documentation comments

## Performance Characteristics

### Time Complexity

| Operation | Complexity | Notes |
|-----------|-----------|-------|
| Index building | O(n) | Single pass through rustdoc.json |
| Link resolution | O(1) | Hash map lookup |
| Document processing | O(m) | m = number of links in document |
| **Total build** | O(n + m*d) | n = rustdoc items, m = docs, d = links per doc |

### Space Complexity

- Index: O(n) where n = number of rustdoc items (~0.1-0.5MB per 1000 items)
- Per-document processing: O(1) - no per-document state

### Optimization Techniques

1. **Single index build**: Built once, reused across all documents
2. **Hash-based lookup**: O(1) resolution instead of O(n) search
3. **Lazy parsing**: Only processes needed JSON sections
4. **Early bailout**: Returns empty index if JSON doesn't exist

## Known Limitations

1. **No full-text search** across both prose and API docs (future enhancement)
2. **No embedding** of rustdoc HTML snippets (stays as link)
3. **JSON format version** locked to Rust's rustdoc format (~v28)
4. **No cross-crate linking** currently (each crate has own JSON)
5. **Requires rustdoc.json** - older Rust versions don't support `--output-format json`
