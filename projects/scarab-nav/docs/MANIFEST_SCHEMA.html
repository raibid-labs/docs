Plugin Manifest Schema

This document describes the schema for the plugin.toml manifest file used by scarab-nav.

Overview

The plugin manifest defines metadata, capabilities, and dependencies for the scarab-nav plugin. It follows the fusabi-plugin-runtime manifest schema version 0.1.0.

Schema Version

Current schema version: 0.1.0

Based on: fusabi-plugin-runtime v0.1.1

Full Manifest Structure

Section Reference

Defines the manifest version and schema.

FieldTypeRequiredDescription

FieldTypeRequiredDescription

Plugin Types:

  • native: Compiled Rust library (.so, .dll, .dylib)
  • wasm: WebAssembly module
  • script: Interpreted script (Lua, Python, etc.)

Validation

Required Fields

At minimum, a valid manifest must have:

Validation Rules

  1. Semantic Versioning: All version fields must be valid semver
  2. Name Format: Plugin name must be lowercase, alphanumeric, hyphens only
  3. License: Must be a valid SPDX identifier
  4. URLs: Must be valid HTTP/HTTPS URLs
  5. Capabilities: Must use known capability namespaces
  6. Keywords: Maximum 5 keywords
  7. Schema Version: Must match a supported runtime schema version

Schema Changes

Version 0.1.0 (Current)

Initial schema version.

Features:

  • Basic plugin metadata
  • Capability declaration
  • Dependency management
  • Package information
  • Compatibility constraints

Limitations:

  • No plugin dependencies (plugins can’t depend on other plugins)
  • No conditional capabilities (based on platform/feature)
  • No resource limits (memory, CPU, etc.)

These may be addressed in future schema versions.
